# T111 — Secret 회전·유출 대응 초안

**DRAFT / NOT_EXECUTED**. 실환경 절차 리뷰와 실행 승인이 남아 있습니다.
이 문서 작성이나 예시 검사 성공은 회전 완료 증빙이 아닙니다.
[환경 계약](ENVIRONMENT_CONTRACT.md)과 [보안 규정](../SECURITY.md)을 함께 적용합니다.

## 정상 회전 준비

1. PM/JM이 대상 Secret의 관리 주체, 소비 서비스, 권한, 만료, 교체 사유와 작업 시간을
   확정합니다. 변경 기록에는 실제 값 대신 내부 참조 ID와 시간만 적습니다.
2. 기존 자격증명을 읽거나 출력하지 않고 소비 경로를 확인합니다. GitHub Actions의
   실행 토큰, systemd credential의 GHCR 읽기 자격증명, DB 계정은 별개 대상입니다.
3. 앱 계정·조회 계정·Migration 계정·관리자 계정을 구분하고 최소권한을 검토합니다.
   현재 PoC의 bootstrap 사용자 정보를 정식 앱 계정 정책으로 승인하지 않습니다.
4. 승인된 Secret 저장 경로와 복구 절차를 준비합니다. 가상 자격증명을 사용하는 격리
   환경에서 먼저 리허설하고, 실제 공유 DB나 자동배포 설정 변경은 별도 승인 대상으로 둡니다.

## 승인된 환경에서 실행할 때의 확인점

1. 운영자가 승인된 방식으로 새 자격증명을 발급하고 소비 서비스에 전달합니다.
   코드·PR·시트·대화·CI 로그에는 값이나 연결 문자열을 기록하지 않습니다.
2. 소비 서비스의 새 인증과 필요한 최소 작업을 확인합니다. DB는 허용 쿼리와
   금지 DDL/권한 경계를, 배포 자격증명은 필요한 읽기 범위를 검증합니다.
3. 헬스·오류율·배포 상태를 확인한 다음 구 자격증명을 폐기하고, 구 인증이 실제로
   거부되는지 검증합니다. 검증 실패는 성공으로 기록하지 않습니다.
4. 변경 시각, 대상 참조 ID, 실행·승인자, 성공/거부 검증 결과와 복구 여부를 기록합니다.
   무중단 여부는 관측한 요청·상태의 근거가 있을 때만 표시합니다.

리허설에서 서비스 중단이 확인되거나 소비 경로를 특정하지 못하면 운영 적용은 HOLD입니다.
공유 DB 초기화·볼륨 삭제·전체 Docker 정리로 복구하지 않습니다. 앱 CD에 Migration이나
자격증명 변경 SQL을 자동 연결하지 않습니다.

## 유출이 의심되는 경우

1. 공개 게시나 추가 전송을 멈추고 대상·권한·노출 시각을 값 없이 기록해 승인된 보안
   연락 경로로 알립니다. 노출 문자열을 보고서에 다시 복사하지 않습니다.
2. 관리 주체가 영향 범위와 긴급 폐기·교체를 판단합니다. 저장소에서 문자열을 지운
   것만으로 사고가 해결되었다고 판단하지 않습니다.
3. 승인된 범위에서 접근 기록과 비정상 사용을 확인하고, 소비자 반영·구 인증 거부·서비스
   복구를 검증합니다. 기록을 삭제하거나 확인하지 않은 항목을 PASS로 표시하지 않습니다.

실제 Secret 조회·발급·교체·폐기는 이번 작업에서 수행하지 않았습니다.
