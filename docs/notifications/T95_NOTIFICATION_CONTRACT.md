## 1. 알림 유형과 중요도

| 분류 | 중요도 | 예 | 필수 여부 |
|---|---|---|---|
| 계정 보안 | 최상 | 비밀번호 재설정·변경, 새 로그인 | **필수** — 마케팅 동의와 무관, 끌 수 없음 |
| 이메일 인증 | 최상 | 인증 링크 | 필수 |
| 계정 복구 | 최상 | 복구 안내 | 필수 |
| 서비스 안내(정책 변경) | 상 | 약관·처리방침 변경 | 필수(법적 고지) |
| 서비스 안내(점검) | 중 | 점검 예정 | 선택(`service_updates`) |
| 추천 결과 | 하 | 새 맞춤 추천 | 선택(`recommendation_alerts`), 기본 끔 |
| 선택적 마케팅 | 하 | 뉴스레터 | 선택(`marketing_notification`), 기본 끔, 야간 금지 |

**필수 보안 알림과 마케팅 수신 동의를 섞지 않습니다.** 마케팅 동의를 철회해도 보안 알림은 계속 발송되고, 보안 알림에는 광고 내용을 넣지 않습니다.

## 2. 채널

| 채널 | 1차 이후 제안 | 비고 |
|---|---|---|
| email | 기본 | 공급자 미정(T93 Mock 발송 어댑터 재사용 → 공급자 연결 시 교체) |
| in_app | 후보 | 화면 내 알림함(별도 UI 일감) |
| push / SMS | 보류 | 앱 없음, SMS 비용·번호 수집(개인정보 추가) 문제 |

## 3. 수신 설정 규칙

1. 선택 알림은 **해당 동의의 최신 행이 `granted=true`일 때만** 보냅니다(`user_consents` 최신 행 기준, T31 방식).
2. 동의 철회 직후부터 새 선택 알림은 차단합니다. 이미 대기열에 있는 선택 알림도 발송 직전에 다시 확인해 취소합니다(T51 worker 재확인 방식).
3. 필수 알림은 동의와 무관하게 발송합니다. 단 **비활성(탈퇴 접수) 계정에는 탈퇴 처리 안내 외 아무것도 보내지 않습니다.**
4. 조용한 시간(사용자 시간대 21:00~08:00)에는 "적용" 유형을 다음 08:00으로 미룹니다. 보안·인증·복구는 즉시 보냅니다.
5. 수신 설정 변경 자체는 동의 이력으로 남깁니다(추가만).

## 4. 중복 방지

- 묶음 키 = `sha256(user_id | type | subject_ref)`, 유형별 창(표의 "중복 방지 창") 안에서 1회만 보냅니다. `subject_ref`는 대상 식별자(예: 추천 실행 id)이고, 없으면 빈 값입니다.
- 같은 키가 대기 중이면 새 요청을 합칩니다(최신 내용으로 덮어쓰지 않음 — 이미 승인된 템플릿 값만 사용).

## 5. 전송 실패와 재시도

| 항목 | 규칙 |
|---|---|
| 일시 실패(공급자 5xx·timeout) | 지수 백오프 1분 → 5분 → 30분 → 2시간 → 6시간, 유형별 최대 횟수(표). 첫 시도 포함 |
| 영구 실패(주소 없음·거부) | 재시도하지 않음, 기록 `failed_permanent` |
| 최대 횟수 초과 | `failed`. 보안 유형은 운영 알림(관리자 화면, T85 연계 후보) |
| 재시도 중 동의 철회·계정 비활성 | 다음 시도 전 다시 확인해 `cancelled` |
| 대기열 | DB 기반 outbox(제안) — 요청 트랜잭션과 같이 기록해 유실 방지. T93의 "즉시 3회 재시도" 방식은 대기열 도입 전 임시 |

## 6. 발송 기록·보존 (`database/migrations/0005_notifications.sql`, 운영 적용 전)

`notification_deliveries`(제안):

| 컬럼 | 설명 |
|---|---|
| delivery_id, user_id(FK users **SET NULL**) | 탈퇴 후 익명화(T87 분류: ANONYMIZE) |
| type, channel, status(`queued/sent/failed/failed_permanent/cancelled`), attempts, dedupe_key | 처리 상태 |
| template_code, template_version | 승인된 템플릿만 |
| created_at, sent_at, next_attempt_at | 시각 |

- **저장하지 않는 것**: 메일 본문, 링크·토큰, 수신 주소 원문(필요하면 HMAC만), 공급자 응답 원문
- 보존 기간: 유형별 표 값(보안·탈퇴 안내 1년, 그 외 90일). **법무 확인 전 제안값**입니다.
- 감사: 수신 설정 변경은 동의 이력으로 충분합니다. 발송 자체는 감사 이벤트가 아닙니다(대량). 보안 알림 실패는 운영 경보로 처리합니다.

## 7. 템플릿 승인

| 단계 | 기준 |
|---|---|
| 작성 | `template_code`·버전·문구(한국어), 광고 여부 표시, 개인정보 최소(이름 대신 "회원님") |
| 검토 | 보안 알림에 광고 문구 없음, 링크는 우리 도메인만, 토큰은 링크에만 |
| 승인 | PM(+법무: 마케팅·정책 변경) 승인 기록 → 표의 "템플릿 승인"을 "승인(날짜)"로 |
| 사용 | 미승인 템플릿은 발송 거부(코드에서 검사) |

현재 모든 템플릿이 **미승인**입니다.

## 8. API·DTO 제안 (OpenAPI 조각 별도 파일)

- `GET /api/v1/me/notification-preferences` → `NotificationPreferences { items: [{ type, required, enabled, consent_policy_code|null, channels[] }] }`
  - 필수 유형도 목록에 보여 주되 `required: true`, `enabled: true`이고 바꿀 수 없습니다.
- `PUT /api/v1/me/notification-preferences` → 본문 `{ items: [{ type, enabled }] }`
  - 필수 유형을 끄려 하면 422.
  - 내부적으로 해당 동의 코드의 동의 이력을 추가합니다(T31과 같은 방식).
- 관리자 발송 현황 조회는 T96/T97 범위입니다.
