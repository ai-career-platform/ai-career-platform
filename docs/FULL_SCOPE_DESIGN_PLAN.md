## 1. 설계-구현 원칙

1. **Big Picture First:** 화면·사용자·업무 흐름·도메인·API·AI 파이프라인·데이터 계약·역할/권한·배포를 먼저 하나의 베이스라인으로 묶는다.
2. **Build in Increments:** DB Migration·Seed·Backend·Frontend·AI 기능은 의존관계와 기능별 Vertical Slice 순서로 단계 구현한다.
3. **Contract First:** 전체 테이블/컬럼·API/DTO·화면 ID를 추적 가능하게 연결한 후 팀원별 범위를 배분한다.
4. **Versioned Change:** 전체 설계 승인 이후 변경은 요구사항 ID, ERD/API/화면 영향, Migration 및 테스트를 동반한다.
5. **Preserve Staging:** 자동 앱 배포와 DB Migration은 분리하며, 기존 PostgreSQL 컨테이너/Named Volume과 백업·복원 증빙을 보존한다.
6. **No Invented Requirements:** 아직 확인되지 않은 기능은 ‘후보’로 표시하고 사용자 스토리·기획서·Redmine 근거가 확보될 때까지 확정하지 않는다.

## 4. 단기 프로젝트 실행 순서 — 설계는 전체, 개발은 증분

- **Phase A 전체 설계 베이스라인(선행):** S01~S07을 함께 정의·검토하고 승인. 테이블 수, 화면 수, AI 모델 수는 추정과 확정 구별.
- **Phase B 인프라·데이터 기반:** 승인된 전체 스키마를 버전별 Migration으로 계획; DB 역할/권한, 기준 Seed, 백업/복원·보안 검증. 마이그레이션 실행은 단계별.
- **Phase C 핵심 기능 Vertical Slices:** 사용자/프로필 → 기업·공고 → 역량·직무 → 매칭·Gap 등 의존 관계에 맞춰 병렬 개발.
- **Phase D AI·LLM 통합:** 데이터 계약/모델/추론/추천/RAG/Agent 연결, 품질·비용·권한 검증.
- **Phase E 전체 E2E·릴리스:** 화면↔API↔DB↔AI 통합, 역할/보안/회귀 테스트, Staging 운영 가이드와 개발자 온보딩 재현.
