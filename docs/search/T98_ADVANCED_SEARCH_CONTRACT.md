## 1. 현재(확정)와 제안의 차이

| 항목 | 현재 `GET /api/v1/job-postings` (T18, 확정) | 제안 |
|---|---|---|
| 검색어 `q` | 제목 부분 일치 | **제목 또는 기업명** 부분 일치, 앞뒤 공백 제거·연속 공백 1칸 |
| 기업·직무 | `company_id`·`job_role_id` 각 1개 | 각 최대 10개, 여러 개면 OR (값 1개는 지금과 같음) |

| 마감 포함·정렬·페이지 | `include_closed`, `-published_at`·`expires_at`, 서명 cursor | **그대로** (규칙을 §5에 명문화) |

## 3. 검증 규칙 (위반 = 422 `VALIDATION_FAILED`)

| 매개변수 | 규칙 |
|---|---|
| `q` | 앞뒤 공백 제거·연속 공백 1칸으로 바꾼 뒤 1~100자. 공백뿐이면 422. 대소문자 무시. `%`·`_`·`\`는 **문자 그대로**(LIKE 와일드카드 아님) |
| `company_id`·`job_role_id` | UUID, **중복 제거 전** 10개 이하 |
| `employment_type` | `full_time`·`contract`·`intern`·`part_time`, 4개 이하 |
| `region` | §4 코드, 5개 이하 |
| `posted_within` | `1d`·`3d`·`7d`·`30d` |
| `sort` | `-published_at`(기본)·`expires_at` |
| `limit` | 1~100(기본 20) |
| 알 수 없는 매개변수 | 무시(현재 FastAPI 동작 유지) |

- 같은 값을 여러 번 보내면 한 번으로 봅니다. 값 순서는 의미가 없습니다.
- **SQL 주입 방지**: 모든 값은 바인딩 변수로만 전달합니다(문자열 연결 금지). 열거형은 서버가 허용 목록으로 검사합니다.

## 5. 결합·정렬·페이지·기준 시점

- **결합**: 서로 다른 조건은 AND, 한 조건 안 여러 값은 OR. 조건이 없으면 기본 목록(게시 중)입니다.
- **값이 없는 공고**: `employment_type`·`region`·`job_role_id` 필터를 쓰면 그 값이 NULL인 공고는 제외됩니다.
- **정렬(안정)**: `-published_at` = 게시일 내림차순, 동률이면 `job_posting_id` 내림차순. 마감 포함 목록에서 게시일 없는 공고는 맨 뒤. `expires_at` = 마감일 오름차순, **마감일 없음은 맨 뒤**, 동률이면 id 오름차순.
- **페이지**: keyset cursor(정렬 키 + id). 같은 조건으로 끝까지 넘기면 중복·누락이 없습니다.
- **cursor 묶임**: cursor는 정규화한 조건(§3)의 digest에 서명으로 묶입니다. 순서·중복만 다른 같은 조건은 같은 cursor를 받아들이고, 조건이 다르면 400 `INVALID_CURSOR`입니다.
- **기준 시점**: "게시 중"·`posted_within`은 **각 요청의 서버 시각**으로 판정합니다. 페이지를 넘기는 사이에 마감된 공고는 다음 페이지부터 빠질 수 있습니다. 이미 받은 공고가 다시 나오지는 않습니다(keyset). 스냅샷 고정(`as_of`)은 제안하지 않습니다(D-4).
- **빈 결과**: `200 { "items": [], "next_cursor": null }` — 오류가 아닙니다. 화면은 "조건에 맞는 공고가 없습니다"와 필터 초기화를 안내합니다(T100).

## 6. 화면 계약 (T100 입력)

| 항목 | 규칙 |
|---|---|
| URL 상태 | 화면 URL 쿼리 = API 쿼리와 같은 이름·값(`?q=…&employment_type=a&employment_type=b&region=seoul`). 공유·뒤로가기로 같은 결과 |
| URL에 넣지 않는 것 | 사용자 ID·이메일·북마크 여부 등 비공개 정보, cursor(첫 페이지부터 다시) |
| 기본값 생략 | `sort=-published_at`, `include_closed=false`, `limit`는 URL에 쓰지 않음 |
| 잘못된 URL 값 | 화면이 모르는 값은 버리고 기본값으로 시작(API 422를 사용자에게 보여 주지 않음) |
| 필터 초기화 | `q`·필터 전부 제거, 정렬은 유지 |
| 지역 표시 | "근무지 표기 기준 추정" 안내 |

## 7. 성능 목표 (제안, T99가 측정)

격리 DB 합성 공고 100,000건, 단일 프로세스, 동시성 1: 고급 필터 조합의 서버 처리 p95 < 150 ms, 결과 페이지 20건. 인덱스 후보(T99 EXPLAIN으로 결정): 게시 중 부분 인덱스(`status='published'`), 고용형태·게시일 복합, 지역 판정식 함수 인덱스, 제목·기업명 부분 일치는 `pg_trgm` GIN(확장 설치 권한 확인 필요, D-5).

## 8. 수용 시험

[`t98_acceptance_cases.json`](t98_acceptance_cases.json): 합성 공고 10건(게시 중·만료·closed·draft, NULL 근무지, `%`·`_` 포함 이름)에 대해

`test_t98_search_contract.py`는 §3~§5를 옮긴 참조 판정 함수가 손으로 쓴 기대값과 일치하는지, 제안 OpenAPI가 프로젝트 검사기를 통과하는지 확인합니다. T99는 같은 JSON을 실제 PostgreSQL·API에 돌립니다.
