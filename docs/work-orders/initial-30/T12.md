# T12 — 승인된 Staging Migration·Seed 적용

> **상태:** READY_FOR_REVIEW (착수/완료를 의미하지 않음)  
> **담당 역할:** DB/운영 · **우선순위:** P0 · **실제 담당자:** 미배정  
> **선행 일감:** T07,T08,T09,T10,T11 · **기준 브랜치:** `main`  
> **작업 종류:** 개발 전 1차 작업지시서 후보 · PM/담당자 승인 필요

## 1. 목적과 작업 범위
기존 staging DB 백업과 복원 가능성 검증 후 승인된 전체 DDL/Seed를 버전별 적용하고 Backend 상태 검증.

## 2. 작업 수행 지시
1. 작업 시작 전에 `main`과 연결된 `docs/FULL_SCOPE_TRACEABILITY.md`, `docs/API_CONTRACT.md`, `database/FULL_DATABASE_MODEL.md` 중 관련 문서를 읽고 미확정 요구사항을 기록합니다.
2. **DB 백업 파일 목록 및 격리 복원 PASS 재검증; PM/JM 실행 승인 확보; DB maintenance window 지정; 변경 전후 동일 DB/볼륨·기존 Backend DB Health 비교.**
3. 기존 운영과 분리된 개인 브랜치(`task/t12-short-name`)에서 작업하고, 관련 코드·테스트·설명서를 함께 작성합니다.
4. 가능하면 로컬 또는 일회용 DB에서 먼저 검증하고, 승인 없이 공유 Staging DB·서비스를 변경하지 않습니다.

## 3. 산출물
database/STAGING_MIGRATION_EVIDENCE.md; schema/seed 검산; 백업/복구 기록.

## 4. 완료 기준 (Definition of Done)
- 승인 스키마/Seed/권한 PASS, 기존 데이터 보존, 다운타임과 정상화 증빙.
- 테스트·실행 결과와 재현 명령을 PR 설명에 기록합니다.
- 문서/코드/테스트의 PR 리뷰 완료 및 CI 결과를 확인합니다. CI가 범위를 검증하지 못하면 `PARTIAL`로 표기합니다.
- 작업과 무관한 파일 변경이 없고 민감정보·비밀번호·토큰이 포함되지 않습니다.

## 5. 필수 증빙
- 실제 실행 명령 또는 UI 캡처(비밀정보 마스킹)
- 정상 및 예외/거부 케이스 각각 1개 이상 (해당되는 경우)
- PR URL, 테스트 실행 SHA, 영향 범위와 미해결 항목

## 6. 주의·작업 중단 조건
DB 초기화/볼륨 삭제 절대 금지; compose down -v 금지; 승인 없는 ALTER ROLE 금지.
