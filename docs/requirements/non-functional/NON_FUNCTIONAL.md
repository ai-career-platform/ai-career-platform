# 비기능 요구사항 (NFR)

[목차로](../README.md)

## 양식

모든 비기능 요구사항은 아래 7개 항목을 같은 순서로 적습니다.

| 항목 | 적는 내용 |
|---|---|
| 요구사항명 | 품질 기준을 한 줄로 |
| 우선순위 | Must / Should / Could |
| 사용자 스토리 | 이 기준이 필요한 사람과 이유 |
| 설명 | 지켜야 할 내용 |
| 적용 대상 | 적용되는 기능·요구사항 |
| 측정 기준 | 통과 여부를 판단하는 수치·조건 |
| 검증 방법 | 확인 방법과 담당 일감 |

| 분류 | ID |
|---|---|
| 보안 | NFR-SEC-001 ~ 004 |
| 개인정보 | NFR-PRV-001 ~ 003 |
| 성능 | NFR-PER-001 ~ 002 |
| 가용성 | NFR-AVL-001 ~ 002 |
| AI 품질 | NFR-AIQ-001 ~ 002 |
| 운영 | NFR-OPS-001 ~ 002 |
| 사용성 | NFR-USE-001 ~ 002 |

## 보안

### NFR-SEC-001 인증 정보 보호

| 항목 | 내용 |
|---|---|
| 요구사항명 | 비밀번호와 로그인 토큰을 안전하게 저장·전송 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, 데이터가 유출돼도 내 비밀번호가 드러나지 않기를 원한다. |
| 설명 | 비밀번호는 복원할 수 없는 해시로 저장한다. 로그인 토큰은 짧은 접근 토큰(15분)과 갱신 토큰(14일)으로 나누고, 갱신 토큰은 브라우저 스크립트가 읽을 수 없는 쿠키에 담는다. 서버에는 토큰 해시만 저장한다. |
| 적용 대상 | FR-ACC-001 ~ 004 |
| 측정 기준 | 1. DB·로그·오류 응답에 비밀번호·토큰 원문이 없다.<br>2. 갱신 토큰은 쓸 때마다 새 토큰으로 바뀌고, 이전 토큰은 즉시 무효가 된다.<br>3. 모든 통신은 HTTPS로만 한다. |
| 검증 방법 | 인증 API 테스트, DB 컬럼 점검 (T15) |

### NFR-SEC-002 권한 검사

| 항목 | 내용 |
|---|---|
| 요구사항명 | 모든 요청에서 서버가 소유권과 역할을 확인 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, 다른 사람이 내 프로필·문서·분석 결과를 볼 수 없기를 원한다. |
| 설명 | 개인 데이터는 로그인한 본인 것만 조회·변경할 수 있다. 화면에서 메뉴를 숨기는 것과 별개로 서버가 매 요청 확인한다. 다른 사람 데이터 요청은 "찾을 수 없음"으로 응답해 존재 여부도 알리지 않는다. |
| 적용 대상 | 로그인이 필요한 모든 기능, FR-ADM 전체 |
| 측정 기준 | 1. 사용자 A가 사용자 B의 데이터 ID로 요청하면 모두 거부된다.<br>2. 관리자 기능은 관리자 역할 없이 호출하면 거부된다.<br>3. 역할 회수 후 다음 요청부터 거부된다. |
| 검증 방법 | 권한 회귀 테스트 (T29, T86) |

### NFR-SEC-003 업로드 파일 검사

| 항목 | 내용 |
|---|---|
| 요구사항명 | 업로드 파일의 형식·크기·악성 여부 검사 |
| 우선순위 | Must |
| 사용자 스토리 | 운영 관리자로서, 악성 파일이 서버와 다른 사용자에게 퍼지지 않기를 원한다. |
| 설명 | 파일 형식은 확장자가 아니라 실제 내용으로 확인하고, 크기를 제한하며, 사용 전에 악성 여부를 검사한다. 저장 위치는 사용자에게 공개하지 않는다. |
| 적용 대상 | FR-AI-001 |
| 측정 기준 | 1. PDF·DOCX 외 파일, 10MB 초과 파일, 확장자만 바꾼 파일은 모두 거부된다.<br>2. 검사를 통과하지 않은 파일은 분석·검색에 쓰이지 않는다. |
| 검증 방법 | 업로드 API 테스트 (T49) |

### NFR-SEC-004 AI 입력 보호

| 항목 | 내용 |
|---|---|
| 요구사항명 | 문서·질문 속 악의적인 지시문 차단 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, 누군가 문서에 숨긴 문장 때문에 AI가 엉뚱하게 동작하지 않기를 원한다. |
| 설명 | 문서 내용과 검색 결과는 AI에게 "참고 자료"로만 전달하고 지시로 취급하지 않는다. AI가 데이터를 바꾸는 작업은 사용자 승인을 거친다. |
| 적용 대상 | FR-AI-002 ~ 004 |
| 측정 기준 | 1. 지시문을 넣은 테스트 문서로 분석·Q&A를 해도 정해진 동작 외에 하지 않는다.<br>2. 승인 없는 데이터 변경이 0건이다. |
| 검증 방법 | LLM 안전성 평가 (T109) |

## 개인정보

### NFR-PRV-001 최소 수집

| 항목 | 내용 |
|---|---|
| 요구사항명 | 기능에 필요한 개인정보만 수집 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, 필요 이상으로 내 정보를 내주고 싶지 않다. |
| 설명 | 필수 정보는 이메일·비밀번호·표시 이름뿐이다. 나머지는 선택 입력이다. Q&A 질문 원문은 저장하지 않는다. 이용 기록은 동의한 사용자만 수집한다. |
| 적용 대상 | FR-ACC-001, FR-ACC-005, FR-AI-003, FR-ADM-006 |
| 측정 기준 | 1. 가입 시 필수 입력은 3개다.<br>2. 질문 원문을 저장하는 테이블·로그가 없다.<br>3. 동의하지 않은 사용자의 이용 기록이 0건이다. |
| 검증 방법 | 데이터 사전 점검, 수집 API 테스트 (T05, T72) |

### NFR-PRV-002 보존·삭제

| 항목 | 내용 |
|---|---|
| 요구사항명 | 정해진 기간이 지난 데이터와 탈퇴 사용자 데이터 삭제 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, 탈퇴하면 내 정보가 실제로 지워지기를 원한다. |
| 설명 | 탈퇴 요청 30일 후 개인 데이터를 삭제한다. 감사·비용 기록은 사용자를 알 수 없게 바꿔 1년 보존한다. 로그인 세션은 만료 30일 후, 검색 기록은 90일 후, 이용 기록은 180일 후 삭제한다. 기간은 법무 확인 전 제안값이다. |
| 적용 대상 | FR-ACC-007, 개인 데이터를 저장하는 모든 기능 |
| 측정 기준 | 1. 삭제 예정 시각이 지난 계정의 개인 데이터가 0건이다.<br>2. 감사 기록에 탈퇴 사용자 식별 정보가 없다. |
| 검증 방법 | 탈퇴·보존 E2E 테스트 (T87) |

### NFR-PRV-003 외부 AI 전송

| 항목 | 내용 |
|---|---|
| 요구사항명 | 외부 AI 서비스로 보내는 개인정보 최소화 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, 내 이력서가 동의 없이 외부 서비스로 나가지 않기를 원한다. |
| 설명 | AI 처리 동의를 받은 경우에만 외부 AI로 문서를 보낸다. 보내기 전에 연락처·주소 같은 식별 정보를 가린다. 요청마다 모델·토큰 수·비용·응답 시간만 기록하고 내용은 기록하지 않는다. |
| 적용 대상 | FR-AI-002 ~ 004, FR-ADM-005 |
| 측정 기준 | 1. 동의 없는 사용자 문서의 외부 전송이 0건이다.<br>2. 전송 내용에 이메일·전화번호 형식 문자열이 없다. |
| 검증 방법 | AI 파이프라인 테스트 (T51) |

### NFR-PER-002 목록 조회 제한

| 항목 | 내용 |
|---|---|
| 요구사항명 | 목록은 페이지 단위로 나눠 조회 |
| 우선순위 | Must |
| 사용자 스토리 | 운영 관리자로서, 한 요청이 데이터를 한꺼번에 가져가 서버를 느리게 만들지 않기를 원한다. |
| 설명 | 모든 목록은 한 번에 최대 100개(기본 20개)만 반환하고, 다음 페이지 정보를 함께 준다. 정렬 기준은 미리 정한 값만 허용한다. |
| 적용 대상 | 목록을 보여주는 모든 기능 |
| 측정 기준 | 1. 100개를 넘게 요청하면 거부된다.<br>2. 페이지를 넘겨도 중복·누락이 없다. |
| 검증 방법 | API 계약 테스트 (T06, T29) |

| 항목 | 내용 |
|---|---|
| 요구사항명 | AI·분석 서비스 장애가 기본 기능을 멈추지 않음 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, AI가 고장 나도 로그인·프로필·공고 검색은 계속 쓰고 싶다. |
| 설명 | AI·분석 기능 오류는 해당 화면 영역에만 표시하고, 다른 기능은 정상 동작한다. 추천 실패 시 최신 공고 목록으로 대체한다. |
| 적용 대상 | FR-ANL 전체, FR-AI 전체 |
| 측정 기준 | 1. AI 서비스를 끈 상태에서 FR-ACC·FR-PRF·FR-JOB 기능이 모두 정상 동작한다.<br>2. 장애 시 사용자에게 다시 시도 안내가 보인다. |
| 검증 방법 | 장애 주입 테스트 (T29, T113) |

## AI 품질

### NFR-AIQ-001 분석 결과 표시

| 항목 | 내용 |
|---|---|
| 요구사항명 | 점수의 의미·계산 기준·한계를 함께 표시 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, 점수를 합격 가능성으로 오해하지 않고 어떻게 계산됐는지 알고 싶다. |
| 설명 | 적합도·추천 점수는 0~100점이며 합격 확률이 아님을 표시한다. 모든 분석 결과에 계산 기준 버전, 계산 시각, 한계 설명을 붙인다. |
| 적용 대상 | FR-ANL 전체, FR-AI-002, FR-AI-003 |
| 측정 기준 | 1. 점수를 "%"나 "확률"로 표시하는 화면이 없다.<br>2. 모든 결과 화면에 계산 기준과 한계 설명이 있다. |
| 검증 방법 | 화면 검수, API 응답 점검 (T42, T44, T46) |

### NFR-AIQ-002 재현성

| 항목 | 내용 |
|---|---|
| 요구사항명 | 같은 입력과 같은 계산 기준이면 같은 결과 |
| 우선순위 | Must |
| 사용자 스토리 | 운영 관리자로서, 사용자가 받은 결과를 나중에 다시 확인하고 설명하고 싶다. |
| 설명 | 결과를 계산 기준 버전과 함께 저장하고, 계산에 쓴 값(요구 수준, 보유 숙련도)을 결과에 복사해 둔다. 모델을 바꿀 때는 평가 지표와 데이터 누수 점검 결과를 남긴다. |
| 적용 대상 | FR-ANL-001 ~ 003, FR-ADM-003 |
| 측정 기준 | 1. 같은 입력으로 두 번 계산하면 같은 점수가 나온다.<br>2. 과거 결과를 열면 당시 값으로 보인다. |
| 검증 방법 | 규칙 기반 Baseline 테스트 (T26, T27) |

## 운영

### NFR-OPS-001 기준 데이터 관리

| 항목 | 내용 |
|---|---|
| 요구사항명 | 직무·기술·가상 공고 데이터를 같은 명령으로 반복 적재 |
| 우선순위 | Must |

| 측정 기준 | 1. 적재를 두 번 실행해도 건수가 같다.<br>2. 데이터 출처가 모두 기록돼 있다. |
| 검증 방법 | Seed 테스트 (T10) |

### NFR-OPS-002 DB 변경 승인

| 항목 | 내용 |
|---|---|
| 요구사항명 | 공용 DB 구조 변경은 승인 후 적용 |
| 우선순위 | Must |
| 사용자 스토리 | 운영 관리자로서, 검증되지 않은 변경으로 공용 DB가 깨지지 않기를 원한다. |
| 설명 | 테이블 변경은 일회용 DB에서 먼저 검증하고, 백업 확인과 PM 승인을 거쳐 공용 Staging DB에 적용한다. 앱 자동 배포와 DB 변경은 분리한다. |
| 적용 대상 | DB 변경 전체 |
| 측정 기준 | 1. 승인 기록 없는 Staging DB 변경이 0건이다.<br>2. 모든 변경에 되돌리는 방법이 있다. |
| 검증 방법 | Migration 절차 점검 (T08, T12) |

| 검증 방법 | 화면 검수 (T20) |
