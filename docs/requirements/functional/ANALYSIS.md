# 기능 요구사항 — 분석·추천 (FR-ANL)

[목차로](../README.md) · 양식은 [README](../README.md#기능-요구사항)를 따릅니다.

**공통 표시 규칙** ([NFR-AIQ-001](../non-functional/NON_FUNCTIONAL.md#nfr-aiq-001-분석-결과-표시)): 모든 점수는 0~100점이며 합격 확률이 아니라고 화면에 밝힙니다. 결과마다 계산 기준(규칙·모델 버전)과 계산 시각을 함께 보여줍니다.

---

### FR-ANL-001 적합도 확인

| 항목 | 내용 |
|---|---|
| 요구사항명 | 공고 또는 직무에 대한 적합도 점수와 근거 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, 공고가 내 기술과 얼마나 맞는지 알고 싶다. 지원할 공고를 고르기 위해서다. |
| 설명 | 보유 기술·숙련도와 프로젝트 사용 기술을 공고(또는 직무)의 요구 기술과 비교해 점수, 충족 기술 수, 부족 기술 수, 한계 설명을 보여준다. 1차는 규칙 기반으로 계산한다. |
| 입력 | 공고 또는 직무 중 하나 |
| 출력 | 적합도 점수(0~100), 충족·부족 기술 수, 계산 기준, 한계 설명 |
| 선행 조건 | 로그인 상태, 보유 기술 1개 이상 |
| 수용 기준 | 1. 같은 입력과 같은 계산 기준이면 항상 같은 점수가 나온다.<br>2. 점수 옆에 "합격 확률이 아닙니다"를 표시한다.<br>3. 결과에 계산 기준 버전이 저장되고 화면에 표시된다.<br>4. 부족한 기술을 누르면 그 기술의 Skill Gap 화면으로 이동한다. |
| 예외 처리 | 보유 기술 없음: 기술 등록 화면으로 안내. 계산 서비스 장애: 적합도 영역만 "잠시 후 다시 시도" 표시, 공고 내용은 정상 표시. |
| 관련 화면 | UI-015 적합도 결과, UI-012 |

### FR-ANL-002 Skill Gap 분석

| 항목 | 내용 |
|---|---|
| 요구사항명 | 목표 직무 기준 부족 기술 분석 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, 목표 직무에 필요한 기술 중 무엇이 얼마나 부족한지 알고 싶다. 무엇을 먼저 공부할지 정하기 위해서다. |
| 설명 | 목표 직무의 요구 기술마다 요구 수준, 내 숙련도, 차이를 계산해 차이가 큰 순으로 보여준다. 결과는 계산 시점 값으로 저장해 이력으로 남긴다. |
| 입력 | 목표 직무 하나 |
| 출력 | 기술별 요구 수준·내 숙련도·차이, 계산 기준, 계산 시각 |
| 선행 조건 | 로그인 상태, 목표 직무 1개 이상, 보유 기술 1개 이상 |
| 수용 기준 | 1. 차이 = 요구 수준 − 내 숙련도이며, 0보다 작으면 0으로 표시한다.<br>2. 숙련도를 입력하지 않은 기술은 0으로 계산하고 "숙련도 미입력"을 표시한다.<br>3. 계산 후 보유 기술이나 목표 직무가 바뀌면 결과에 "이전 기준" 표시가 붙는다.<br>4. 부족 기술에서 그 기술을 요구하는 공고 검색으로 이동할 수 있다.<br>5. 부족한 기술이 없으면 "요구 기술을 모두 충족했습니다"를 보여준다. |
| 예외 처리 | 목표 직무 없음: 목표 직무 설정으로 안내. 보유 기술 없음: 기술 등록으로 안내. |
| 관련 화면 | UI-016 Skill Gap, UI-N01 홈 |

### FR-ANL-003 맞춤 공고 추천

| 항목 | 내용 |
|---|---|
| 요구사항명 | 프로필 기반 채용공고 추천 목록 |
| 우선순위 | Should |
| 사용자 스토리 | 구직자로서, 내 프로필에 맞는 공고를 순위대로 받고 싶다. 공고를 하나씩 찾는 시간을 줄이기 위해서다. |
| 설명 | 목표 직무와 보유 기술을 기준으로 게시 중인 공고의 적합도를 계산해 높은 순으로 추천한다. 항목마다 추천 이유를 보여준다. |
| 입력 | 추천 받기 요청(최대 개수 1~50, 기본 20) |
| 출력 | 순위, 공고 요약, 점수, 추천 이유 |
| 선행 조건 | 로그인 상태 |
| 수용 기준 | 1. 마감된 공고와 "관심 없음"으로 표시한 공고는 추천에서 빠진다.<br>2. 모든 항목에 추천 이유가 1개 이상 있다.<br>3. 추천 실행마다 기록을 남겨 피드백과 연결한다.<br>4. 가장 최근 추천은 다시 계산하지 않고 바로 볼 수 있다. |
| 예외 처리 | 프로필 정보 부족: 기술·목표 직무 입력 안내. 추천 계산 실패: 최신 공고 목록을 대신 보여주고 "맞춤 추천을 준비하지 못했습니다" 안내. |
| 관련 화면 | UI-017 맞춤 추천, UI-N01 홈 |

### FR-ANL-004 추천 이유와 피드백

| 항목 | 내용 |
|---|---|
| 요구사항명 | 추천 이유 상세 보기와 좋아요·관심 없음 피드백 |
| 우선순위 | Should |
| 사용자 스토리 | 구직자로서, 추천 이유를 자세히 보고 마음에 들지 않는 공고는 제외하고 싶다. 다음 추천을 내게 더 맞게 하기 위해서다. |
| 설명 | 추천 목록에서 항목을 펼쳐 이유를 자세히 보고, "좋아요", "관심 없음", "선택 취소"를 남긴다. 피드백은 변경 이력으로 저장한다. |
| 입력 | 추천 항목, 피드백 값 |
| 출력 | 저장된 피드백, 목록에 반영된 상태 |
| 선행 조건 | 로그인 상태, 추천 결과 있음 |
| 수용 기준 | 1. 피드백을 바꿔도 이전 기록은 지우지 않는다.<br>2. 공고별로 가장 최근 피드백을 현재 상태로 본다.<br>3. "관심 없음" 공고는 다음 추천에서 빠진다. |
| 예외 처리 | 저장 실패: 화면의 선택 상태를 이전으로 되돌리고 오류 안내. |
| 관련 화면 | UI-017 맞춤 추천 (펼침 영역) |

### FR-ANL-005 채용시장 추세

| 항목 | 내용 |
|---|---|
| 요구사항명 | 직무별 공고 수·기술 수요 추세와 예측 |
| 우선순위 | Could |
| 사용자 스토리 | 구직자로서, 관심 직무의 공고가 늘고 있는지 보고 싶다. 준비할 직무와 기술을 정하는 데 참고하기 위해서다. |
| 설명 | 직무별 지표(공고 수, 기술 수요 비율)를 기간별 그래프로 보여주고, 예측값은 범위와 함께 구분해 표시한다. |
| 입력 | 직무(선택), 지표, 기간 |
| 출력 | 관측값, 예측값과 범위, 데이터 출처 |
| 선행 조건 | 로그인 상태, 시장 데이터 출처 확보 |
| 수용 기준 | 1. 관측값과 예측값을 선 모양·색으로 구분한다.<br>2. 데이터 출처와 집계 기간을 표시한다.<br>3. 데이터가 부족한 구간은 빈 구간으로 표시한다. |
| 예외 처리 | 데이터 없음: "표시할 데이터가 없습니다" 안내. |
| 관련 화면 | UI-024 시장 추세 |
