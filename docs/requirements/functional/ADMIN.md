### FR-ADM-001 관리자 접근 제어

| 항목 | 내용 |
|---|---|
| 요구사항명 | 관리자 역할만 운영 화면 접근 |
| 우선순위 | Must |
| 사용자 스토리 | 운영 관리자로서, 관리 화면을 관리자만 쓰게 하고 싶다. 일반 사용자가 운영 정보를 보지 못하게 하기 위해서다. |
| 설명 | 사용자에게 역할(구직자, 관리자)을 부여하고, 관리 화면과 관리 기능은 관리자 역할만 쓸 수 있게 한다. |
| 입력 | 로그인 사용자의 역할 |
| 출력 | 역할에 맞는 메뉴, 접근 허용·거부 |
| 선행 조건 | 로그인 상태 |
| 수용 기준 | 1. 관리자가 아니면 관리 메뉴가 보이지 않는다.<br>2. 주소를 직접 입력해도 서버가 다시 확인해 접근을 막는다.<br>3. 가입하면 구직자 역할이 자동으로 부여된다. |
| 예외 처리 | 권한 없음: 공통 "접근 권한이 없습니다" 화면. |
| 관련 화면 | UI-C02 공통 내비게이션, UI-C01 공통 상태 |

### FR-ADM-002 역할 부여·회수

| 항목 | 내용 |
|---|---|
| 요구사항명 | 관리자가 다른 사용자의 역할을 부여·회수 |
| 우선순위 | Must |
| 사용자 스토리 | 운영 관리자로서, 새 운영자에게 관리자 역할을 주고 그만둔 운영자의 역할을 바로 회수하고 싶다. 권한을 필요한 사람에게만 두기 위해서다. |
| 설명 | 사용자 검색 후 관리자 역할을 부여하거나 회수한다. 모든 변경은 감사 기록에 남긴다. |
| 입력 | 대상 사용자, 역할, 부여·회수 |
| 출력 | 변경된 역할, 감사 기록 |
| 선행 조건 | 관리자 역할 |
| 수용 기준 | 1. 회수하면 대상 사용자의 다음 요청부터 바로 적용된다.<br>2. 누가, 언제, 누구에게 어떤 역할을 바꿨는지 감사 기록에 남는다.<br>3. 마지막 남은 관리자의 역할은 회수할 수 없다. |
| 예외 처리 | 마지막 관리자 회수 시도: "관리자가 최소 1명 있어야 합니다". |
| 관련 화면 | UI-028 운영 감사 |

### FR-ADM-003 모델 버전·평가 조회

| 항목 | 내용 |
|---|---|
| 요구사항명 | 서비스 중인 계산 기준(규칙·모델) 버전과 평가 지표 조회 |
| 우선순위 | Should |
| 사용자 스토리 | 운영 관리자로서, 지금 어떤 계산 기준이 쓰이고 성능이 어떤지 보고 싶다. 결과 품질을 관리하기 위해서다. |
| 설명 | 적합도·Skill Gap·추천·문서 분석에 쓰는 규칙·모델의 버전 목록과 버전별 평가 지표를 보여준다. |
| 입력 | 버전 선택 |
| 출력 | 버전 목록(종류, 승인 여부, 설명), 평가 지표 |
| 선행 조건 | 관리자 역할 |
| 수용 기준 | 1. 사용자 결과 화면의 "계산 기준"과 같은 버전 이름을 쓴다.<br>2. 승인되지 않은 버전은 "미승인"으로 표시한다.<br>3. 평가 지표마다 평가 데이터와 데이터 누수 점검 여부를 표시한다. |
| 예외 처리 | 평가 없음: "평가 기록이 없습니다". |
| 관련 화면 | UI-026 모델 운영 |

### FR-ADM-004 감사 기록 조회

| 항목 | 내용 |
|---|---|
| 요구사항명 | 중요 작업 기록 조회 |
| 우선순위 | Should |
| 사용자 스토리 | 운영 관리자로서, 권한 변경·탈퇴 요청 같은 중요한 작업 기록을 찾아보고 싶다. 문제가 생겼을 때 원인을 확인하기 위해서다. |
| 설명 | 기간, 작업자, 작업 종류로 감사 기록을 조회한다. 기록은 수정·삭제할 수 없다. |
| 입력 | 기간(필수), 작업자, 작업 종류 |
| 출력 | 감사 기록(시각, 작업자, 작업, 대상, 요청 번호) |
| 선행 조건 | 관리자 역할 |
| 수용 기준 | 1. 기록은 화면과 데이터베이스 어디에서도 수정·삭제되지 않는다.<br>2. 기록에 비밀번호·토큰·문서 내용 같은 민감정보를 남기지 않는다.<br>3. 오류 화면의 요청 번호로 관련 기록을 찾을 수 있다. |
| 예외 처리 | 기간 미입력: 입력 요청. 결과 없음 안내. |
| 관련 화면 | UI-028 운영 감사 |

### FR-ADM-005 AI 사용량·비용 조회

| 항목 | 내용 |
|---|---|
| 요구사항명 | AI 호출량과 추정 비용 집계 |
| 우선순위 | Should |
| 사용자 스토리 | 운영 관리자로서, AI를 얼마나 쓰고 비용이 얼마나 드는지 보고 싶다. 예산을 넘지 않게 관리하기 위해서다. |
| 설명 | 기간별, 기능별, 모델별로 요청 수, 입력·출력 토큰, 추정 비용을 집계한다. |
| 입력 | 기간, 묶음 기준(일·기능·모델) |
| 출력 | 집계표, 그래프 |
| 선행 조건 | 관리자 역할 |
| 수용 기준 | 1. 비용은 "추정치"로 표시한다.<br>2. 질문·문서 원문은 기록하지 않는다.<br>3. 탈퇴한 사용자의 사용량도 사용자를 알 수 없는 상태로 합계에 포함한다. |
| 예외 처리 | 데이터 없음 안내. |
| 관련 화면 | UI-028 운영 감사 |

### FR-ADM-006 사용자 분석

| 항목 | 내용 |
|---|---|
| 요구사항명 | 사용자 그룹 집계와 이상 이용 탐지 결과 관리 |
| 우선순위 | Could |
| 사용자 스토리 | 운영 관리자로서, 어떤 사용자 그룹이 있는지와 비정상 이용을 확인하고 싶다. 서비스 개선과 악용 방지를 위해서다. |
| 설명 | 이용 기록 수집에 동의한 사용자만 대상으로 그룹별 인원을 집계하고, 이상 이용 탐지 결과를 확인·처리(오탐, 해결)한다. |
| 입력 | 처리 상태 변경 |
| 출력 | 그룹별 인원, 이상 이벤트 목록 |
| 선행 조건 | 관리자 역할 |
| 수용 기준 | 1. 개인을 알아볼 수 있는 정보는 보여주지 않는다.<br>2. 인원이 5명 미만인 그룹은 숫자를 가린다.<br>3. 이용 기록 수집에 동의하지 않은 사용자의 기록은 수집하지 않는다. |
| 예외 처리 | 데이터 없음 안내. |
| 관련 화면 | UI-025 사용자 분석 |
