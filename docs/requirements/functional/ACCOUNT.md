### FR-ACC-001 회원 가입

| 항목 | 내용 |
|---|---|
| 요구사항명 | 이메일과 비밀번호로 회원 가입 |
| 우선순위 | Must |
| 사용자 스토리 | 방문자로서, 이메일로 가입하고 싶다. 내 기술과 분석 결과를 저장해 두고 다시 보기 위해서다. |
| 설명 | 이메일·비밀번호·이름을 받아 계정을 만들고, 필수 약관 동의를 함께 받는다. 가입 후 바로 로그인 상태가 된다. |
| 입력 | 이메일(최대 254자), 비밀번호(10~128자), 표시 이름(1~100자), 약관별 동의 여부 |
| 출력 | 생성된 계정, 로그인 세션, 동의 기록 |
| 선행 조건 | 로그인하지 않은 상태 |
| 수용 기준 | 1. 가입 직후 로그인 상태로 홈 화면에 이동한다.<br>2. 이미 가입된 이메일로는 가입할 수 없다. 중복 여부는 아래 규칙으로 만든 **비교용 이메일**로 판단한다.<br>　· 앞뒤 공백을 지우고 모두 소문자로 바꾼다.<br>　· `@` 앞부분에서 `+`와 그 뒤 글자를 지운다. 예: `crasnec+box@gmail.com` → `crasnec@gmail.com`<br>　· `gmail.com`·`googlemail.com`은 `@` 앞부분의 `.`을 지우고 도메인을 `gmail.com`으로 통일한다. 예: `cras.nec@googlemail.com` → `crasnec@gmail.com`<br>3. 사용자가 입력한 이메일은 연락용으로 그대로 저장하고, 비교용 이메일은 중복 검사에만 쓴다.<br>4. 로그인도 비교용 이메일로 찾는다. `crasnec+box@gmail.com`으로 가입했어도 `crasnec@gmail.com`으로 로그인할 수 있다.<br>5. 필수 약관(이용약관, 개인정보 처리방침)에 동의하지 않으면 가입 버튼이 동작하지 않는다.<br>6. 비밀번호는 해시로만 저장한다. |
| 예외 처리 | 이메일 중복(비교용 이메일이 같은 경우 포함): "이미 가입된 이메일입니다" 안내. 형식 오류: 해당 입력란 아래에 오류 표시. 요청이 너무 많으면 잠시 후 다시 시도 안내. |
| 관련 화면 | UI-001 가입·로그인 |

### FR-ACC-002 로그인

| 항목 | 내용 |
|---|---|
| 요구사항명 | 이메일과 비밀번호로 로그인 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, 로그인하고 싶다. 이전에 저장한 기술과 추천 결과를 이어서 보기 위해서다. |
| 설명 | 이메일·비밀번호가 맞으면 로그인 세션을 만든다. 세션은 다른 기기와 구분해 관리한다. |
| 입력 | 이메일, 비밀번호 |
| 출력 | 로그인 세션, 마지막 로그인 시각 갱신 |
| 선행 조건 | 가입된 계정, 계정 상태가 활성 |
| 수용 기준 | 1. 올바른 정보로 로그인하면 원래 보려던 화면(없으면 홈)으로 이동한다. 이메일은 FR-ACC-001의 비교용 이메일 규칙으로 찾는다.<br>2. 실패 메시지는 이메일이 없는 경우와 비밀번호가 틀린 경우를 구분하지 않는다.<br>3. 같은 계정에 짧은 시간 동안 로그인 실패가 반복되면 일정 시간 시도를 막는다.<br>4. 탈퇴 요청 중인 계정은 로그인할 수 없다. |
| 예외 처리 | 정보 불일치: "이메일 또는 비밀번호가 올바르지 않습니다". 시도 제한: 남은 대기 시간 안내. |
| 관련 화면 | UI-001 가입·로그인 |

### FR-ACC-003 로그아웃·세션 관리

| 항목 | 내용 |
|---|---|
| 요구사항명 | 로그아웃과 로그인 기기 관리 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, 공용 PC에서 로그아웃하고 다른 기기의 로그인도 끊고 싶다. 다른 사람이 내 정보를 보지 못하게 하기 위해서다. |
| 설명 | 현재 세션을 끝내는 로그아웃과, 로그인된 기기 목록 조회·개별 종료를 제공한다. 로그인 유지 시간이 지나면 자동으로 로그아웃된다. |
| 입력 | 로그아웃 요청, 종료할 세션 |
| 출력 | 종료된 세션, 로그인 기기 목록(기기 정보, 로그인 시각, 현재 기기 여부) |
| 선행 조건 | 로그인 상태 |
| 수용 기준 | 1. 로그아웃 후에는 이전 세션으로 내 정보를 조회할 수 없다.<br>2. 기기 목록에서 다른 기기를 종료하면 그 기기는 다음 요청부터 로그아웃 상태가 된다.<br>3. 로그인 유지 시간(14일)이 지나면 다시 로그인해야 한다.<br>4. 작업 중 세션이 끝나면 로그인 후 원래 화면으로 돌아온다. |
| 예외 처리 | 이미 끝난 세션 종료 요청: 목록에서 사라진 것으로 처리. |
| 관련 화면 | UI-002 계정 보안, UI-C02 공통 내비게이션 |

### FR-ACC-004 비밀번호 재설정

| 항목 | 내용 |
|---|---|
| 요구사항명 | 이메일 인증을 통한 비밀번호 재설정 |
| 우선순위 | Should |
| 사용자 스토리 | 구직자로서, 비밀번호를 잊었을 때 다시 설정하고 싶다. 계정을 잃지 않기 위해서다. |
| 설명 | 가입 이메일로 재설정 링크를 보내고, 링크에서 새 비밀번호를 설정한다. 메일 발송 기능이 필요해 1차 일정에 따라 조정한다. |
| 입력 | 이메일, 새 비밀번호 |
| 출력 | 재설정 메일, 변경된 비밀번호, 기존 세션 전체 종료 |
| 선행 조건 | 가입된 계정, 메일 발송 수단 확보 |
| 수용 기준 | 1. 가입 여부와 관계없이 같은 안내 문구를 보여준다.<br>2. 재설정 링크는 한 번만 쓸 수 있고 30분 후 만료된다.<br>3. 비밀번호를 바꾸면 모든 기기에서 로그아웃된다. |
| 예외 처리 | 만료·사용된 링크: 다시 요청하도록 안내. |
| 관련 화면 | UI-N03 계정 복구 |

### FR-ACC-005 프로필 관리

| 항목 | 내용 |
|---|---|
| 요구사항명 | 내 프로필 조회·수정 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, 이름·한 줄 소개·희망 지역을 적어 두고 싶다. 추천과 분석에 반영되게 하기 위해서다. |
| 설명 | 표시 이름, 한 줄 소개, 자기소개, 희망 지역을 조회·수정한다. 프로필은 본인만 볼 수 있다. |
| 입력 | 표시 이름(1~100자), 한 줄 소개(최대 200자), 자기소개(최대 5,000자), 희망 지역(최대 120자) |
| 출력 | 저장된 프로필 |
| 선행 조건 | 로그인 상태 |
| 수용 기준 | 1. 수정한 항목만 바뀌고 나머지는 그대로 유지된다.<br>2. 항목을 비우면 빈 값으로 저장된다(표시 이름은 비울 수 없음).<br>3. 다른 사용자의 프로필은 어떤 방법으로도 조회할 수 없다. |
| 예외 처리 | 글자 수 초과: 입력란 아래 오류 표시, 저장하지 않음. |
| 관련 화면 | UI-003 내 프로필, UI-N02 온보딩 |

### FR-ACC-006 약관 동의 관리

| 항목 | 내용 |
|---|---|
| 요구사항명 | 약관·처리방침 동의 현황 조회와 선택 항목 동의·철회 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, 내가 동의한 항목을 확인하고 선택 항목은 철회하고 싶다. 내 정보가 어디에 쓰이는지 직접 정하기 위해서다. |
| 설명 | 정책별 현재 동의 상태와 변경 이력을 보여준다. 정책은 필수 항목(이용약관, 개인정보 처리방침)과 선택 항목(AI 처리 동의, 이용 기록 수집 동의)으로 나뉘며, **동의·철회는 선택 항목만** 할 수 있다. |
| 입력 | 선택 항목 정책, 정책 버전, 동의 여부 |
| 출력 | 정책별 현재 동의 상태, 변경 이력 |
| 선행 조건 | 로그인 상태 |
| 수용 기준 | 1. 선택 항목에만 동의·철회 스위치를 보여준다.<br>2. 필수 항목은 "필수" 표시와 동의한 날짜만 보여주고 바꾸는 버튼을 두지 않는다. 서비스 이용을 멈추려면 회원 탈퇴(FR-ACC-007)를 안내한다.<br>3. 서버도 필수 항목에 대한 변경 요청은 받지 않는다.<br>4. 동의를 바꿀 때마다 이전 기록을 지우지 않고 새 기록을 추가한다.<br>5. AI 처리 동의를 철회하면 이후 이력서 분석 요청이 거절된다.<br>6. 정책 문서가 새 버전으로 바뀌면 다시 동의를 받는다. |
| 예외 처리 | 저장 실패: 스위치를 이전 상태로 되돌리고 오류 안내. |
| 관련 화면 | UI-005 개인정보 설정 |

### FR-ACC-007 회원 탈퇴

| 항목 | 내용 |
|---|---|
| 요구사항명 | 탈퇴 요청과 개인 데이터 삭제 |
| 우선순위 | Must |
| 사용자 스토리 | 구직자로서, 서비스를 그만 쓸 때 내 정보를 지우고 싶다. 필요 없는 개인정보가 남지 않게 하기 위해서다. |
| 설명 | 탈퇴를 요청하면 계정을 즉시 비활성화하고, 정해진 유예 기간 후 개인 데이터를 삭제한다. 유예 기간 안에는 요청을 취소할 수 있다. |
| 입력 | 탈퇴 확인 문구("DELETE") |
| 출력 | 탈퇴 요청 기록(요청 시각, 삭제 예정 시각, 상태) |
| 선행 조건 | 로그인 상태, 진행 중인 탈퇴 요청 없음 |
| 수용 기준 | 1. 요청 즉시 모든 기기에서 로그아웃되고 다시 로그인할 수 없다.<br>2. 삭제 예정 시각에 프로필·기술·목표 직무·분석 결과·업로드 문서·검색 기록이 모두 삭제된다.<br>3. 감사 기록과 AI 사용량 기록은 사용자를 알 수 없게 바꿔 보존한다.<br>4. 삭제 예정 시각 전에는 탈퇴 요청을 취소할 수 있다.<br>5. 화면에 삭제 대상과 삭제 예정일을 보여준다. |
| 예외 처리 | 이미 요청 중: 기존 요청의 삭제 예정일 안내. 확인 문구 불일치: 진행하지 않음. |
| 관련 화면 | UI-005 개인정보 설정 |
