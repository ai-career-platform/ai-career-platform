# 운영 품질 점검표·대응 플레이북 (T119)

> 상태: **PROPOSED**. 점검 주기·책임자·임계값은 PM 승인 전입니다.
> - 도구: `scripts/ops/t119_scorecard.py`. 읽기 전용이며 loopback 연결만 허용합니다.
> - 임계값: [`quality/t119_thresholds.yaml`](quality/t119_thresholds.yaml)
> - **실측 기준선이 있는 항목은 없습니다.** 각 임계값에 근거(`basis`)를 표시했습니다.
>   - `candidate`: 측정은 있으나 목표 미승인(T88)
>   - `synthetic`: 합성 데이터 기준
>   - `none`: 근거 없음
> - 재학습·재배포·롤백은 하지 않았습니다. 절차만 제안합니다.

## 1. 점검 항목·주기·책임

| 영역 | 항목 | 주기 | 책임(역할) | 근거 |
|---|---|---|---|---|
| 데이터 품질 | 필수 항목 누락률(제목·고용형태·근무지·마감일), 중복률(회사·제목·게시일), 마감 지났는데 게시 중인 비율, 신선도(마지막 게시 후 경과 시간) | 매일(수집 후) | 데이터 담당 | synthetic / none |
| 분포 변화 | 고용형태 분포 PSI(직전 점검 대비). 0.1 주의, 0.25 큰 변화 | 매일 | 데이터 담당 | candidate(관례값) |
| 서비스 SLO | 가용성(5xx 아닌 응답 비율), p95(T112 지연 구간) | 주 1회 검토, 경보는 T113 상시 | Backend 담당 | none / candidate(T88 p95 < 100 ms) |
| AI 품질 | 추천 랭킹 nDCG@10 등 | 모델·규칙 버전 변경 시 + 월 1회 | AI 담당 | **none: T105 미착수, 측정값 없음** |
| 비용 | 이번 달 AI 추정 비용 / 월 예산 | 주 1회 | PM | none(예산 미정) |

판정은 `ok` / `warn` / `breach` / `not_measured` / `no_threshold`입니다. **`not_measured`는 PASS가 아닙니다.**

## 2. 위반 시 조치 (플레이북)

| 항목 | warn | breach | 하지 않는 것 |
|---|---|---|---|
| 누락률·중복률 | 다음 수집에서 원인 확인 | 해당 수집 실행(ingestion run) 격리, 공개 목록에서 숨김 검토 → 수정 수집 | 운영 데이터 직접 삭제 |
| 마감 지난 게시 중 | 만료 처리 배치 확인 | 만료 처리 실행(승인) | — |
| 신선도 | 수집 스케줄 확인 | 수집기 장애 대응(T113) | 미승인 실수집 활성화 |
| 분포 변화(PSI) | 원천 변경 여부 확인(사이트 구조·분류 코드) | 매칭·추천 결과 표본 검토. 모델 버전 롤백 **제안** | 자동 재학습·재배포 |
| 가용성·p95 | 주간 검토 | T113 R2 절차(이전 이미지 롤백, 기능 플래그 끄기) | 승인 없는 운영 설정 변경 |
| AI 품질 | — | 이전 모델·규칙 버전으로 되돌리기 **제안**(T105 기준선 필요) | 측정 없이 품질 주장 |
| 비용 | 상위 기능 확인·보고 | 비용이 드는 기능 플래그 끄기(승인) | — |

### 재학습·롤백 제안 절차
1. 위반 근거(점검표 JSON, 기간, 표본)를 첨부해 PM에게 요청합니다.
2. 격리 환경에서 후보 버전과 현재 버전을 같은 평가 세트로 비교합니다(T105 평가 세트 필요).
3. 승인을 받은 뒤 배포합니다. 롤백 경로는 T90 릴리스 Runbook을 따릅니다.

## 3. 합성 실행 결과 (예시, 실측 아님)

| 실행 | 입력 | 요약 | 주요 판정 |
|---|---|---|---|
| RUN1 | T90 훈련 seed(합성 80건 게시) + 합성 T112 지표 + 예산 50 USD | ok 9 · breach 1 · not_measured 2 | 신선도 315시간 → breach(seed가 오래됨), AI 품질 not_measured |
| RUN2 | 같은 DB에서 정규직 일부를 계약직으로 바꿈(합성 분포 변화) | ok 6 · breach 2 · not_measured 4 | **PSI 0.69 → breach**(변화 감지), 지표·예산을 넣지 않아 SLO·비용은 not_measured |

파일: `quality/T119_SCORECARD_SYNTHETIC_RUN1.json`, `RUN2.json`

## 4. 결정 필요 (PM)
1. 점검 주기와 책임자 지정, 스케줄 등록(운영 변경)
2. SLO 목표(가용성·p95), AI 월 예산
3. T105(추천 평가) 착수: AI 품질 기준선이 없으면 이 영역은 계속 `not_measured`
4. Staging에서 읽기 전용으로 실행할 방법(로컬 복제본 또는 터널, 접속 승인)
