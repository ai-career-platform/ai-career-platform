## 0. 공통 절차

| 단계 | 할 일 | 기준 |
|---|---|---|
| 관측 | `/health`, `/health/db`, 요청 지표(T112 `RequestMetrics`), `app.errors` 오류 코드, AI 사용량, 백업 신선도(T114) | 1분 주기(제안) |
| 탐지 | 규칙이 **연속 N회**(`for_checks`) 충족되면 FIRING. 한 번 흔들리는 것은 무시 | 규칙별 |
| 판단 | 영향 범위(전체/일부 기능), 시작 시각, 최근 배포 SHA(`/version`), request_id로 대표 요청 추적 | 15분 안 확인(ACK) |
| 완화 | 아래 장애별 절차 | — |
| 복원 | 조건 해소 → RESOLVED 알림. 데이터 손상이면 T114 격리 복원·검증 뒤 승인 교체 | — |
| 보고 | 사후 보고서(영향·탐지 경로·원인·완화·재발 방지·남은 위험) | 2영업일 안 |

알림 규칙:
- **중복 억제**: 같은 경보는 30분 동안 다시 알리지 않습니다(SUPPRESSED). 30분이 지나도 계속되면 한 번 더 알립니다(REPEAT).
- **원인 억제**: DB나 API 다운이 울리는 중이면 5xx·지연 경보는 알리지 않습니다(INHIBITED). 같은 장애가 여러 번 울리는 것을 막기 위해서입니다.
- **에스컬레이션**: critical 경보가 15분 안에 확인(ACK)되지 않으면 2차 담당에게 알립니다.
- **연락 경로**(승인 필요):

| 순서 | 대상 | 채널 |
|---|---|---|
| 1차 | 당번 개발자 | `mock-primary` |
| 2차 | PM | `mock-secondary` |

실제 채널(메일·메신저)은 PM 승인 후 정합니다. 그 전에는 Mock 채널만 씁니다.

<a id="r1-db"></a>
## R1. DB 연결 실패 (`A-DB-DOWN`, critical)

- **신호**:
  - `/health/db` 503 `DEPENDENCY_UNAVAILABLE`가 2회 연속 나옵니다.
  - 서버 로그에는 `database error: OperationalError`가 남습니다. 이는 실제 앱으로 재현해 확인했습니다.
- **판단**: `/health`가 200이면 앱 프로세스는 살아 있고 DB 문제입니다.
- **완화**
  1. DB 컨테이너 상태와 디스크 여유를 확인합니다.
  2. 앱 계정의 연결 수 한도(`DB_POOL_SIZE`)를 확인합니다.
  3. 최근 migration 적용 여부를 확인합니다(T115 게이트 기록).
- **복원**: DB가 회복되면 `/health/db`가 200이 되고 RESOLVED 알림이 나갑니다. 일회용 PostgreSQL로 재현해 확인했습니다.
- **금지**: 운영 DB 데이터를 덮어쓰거나 볼륨을 교체하지 않습니다. 손상이 의심되면 T114 절차를 따릅니다.

<a id="r2-api"></a>
## R2. API 5xx·응답 지연 (`A-API-DOWN`, `A-API-5XX`, `A-API-LATENCY`)

- **신호**
  - `/health`가 200이 아님
  - 5분 동안 5xx 비율 5% 초과(요청 20건 이상)
  - p95 1000ms 초과(5회 연속)
- **판단**
  1. `app.access` 로그를 `status>=500`으로 거르고, `request_id`로 `app.errors`의 스택을 찾습니다(T112).
  2. 최근 배포 SHA를 확인합니다.
- **완화**
  - 배포 직후라면 이전 이미지로 되돌립니다(T90 `RELEASE_RUNBOOK.md` 롤백 절차, 정책 변경 없음).
  - 특정 기능만 문제라면 그 기능 플래그를 끕니다(T111 매트릭스의 플래그).
- **보고**: 영향받은 경로와 기간을 기록합니다.

<a id="r3-ai"></a>
## R3. AI·외부 공급자 오류 (`A-AI-PROVIDER`, warning)

- **신호**: `DEPENDENCY_UNAVAILABLE`·`DEPENDENCY_TIMEOUT` 오류가 5분에 5건 이상
- **판단**: 공급자 상태 페이지를 확인하고, 시간 초과인지 인증 실패인지 구분합니다. 키 문제는 T111 회전 Runbook을 따릅니다.
- **완화**
  - 화면은 해당 패널만 오류로 처리합니다(API 계약 §ServiceUnavailable).
  - 재시도는 공급자 한도 안에서만 합니다. 대체 공급자는 미정(PROPOSED)입니다.
- **현재 상태**: 실제 AI 공급자는 연결되어 있지 않습니다(Mock). 이 절차는 연결 후 적용합니다.

<a id="r4-budget"></a>
## R4. AI 과금 한도 (`A-AI-BUDGET-80` warning, `A-AI-BUDGET-100` critical)

- **신호**: 이번 달 `ai_usage_records.estimated_cost_usd` 합계가 월 예산의 80%·100%에 이르면 울립니다. 예산은 PM이 정하며 미정입니다.
- **완화**
  - 80%: 사용량 상위 기능을 확인하고 PM에게 보고합니다.
  - 100%: 비용이 드는 AI 기능 플래그를 끕니다(PM 승인). 이미 받은 요청은 오류 대신 "잠시 사용할 수 없음"으로 안내합니다.
- **주의**: 추정 비용은 공급자 청구와 다를 수 있습니다. 공급자 콘솔의 한도 설정과 함께 씁니다.

<a id="r5-backup"></a>
## R5. 백업 지연 (`A-BACKUP-STALE`, warning)

- **신호**: T114 `freshness` 결과 최신 백업이 24시간보다 오래됐거나 없음
- **완화**: 스케줄러와 디스크를 확인한 뒤 수동 백업을 실행하고, `verify`로 확인합니다(T114 Runbook).
