# T14 PostgreSQL 연결·세션 수명주기 요구사항

T13에서 병합된 FastAPI 앱에 PostgreSQL 연결 풀과 요청 단위 세션을 추가한다. 기준 브랜치는 `main`이며 작업 브랜치는 `task/t14-db-session-lifecycle`이다.

## 선행 조건

| 일감 | 착수 시 확인할 항목 |
| --- | --- |
| [T07](../work-orders/initial-30/T07.md) | 앱용 최소권한 로그인과 허용된 접근 범위의 검증 증빙. 쓰기 검증은 해당 로그인이 준비될 때까지 `HOLD`. |
| [T08](../work-orders/initial-30/T08.md) | 승인된 Migration 실행 방법과 로컬 테스트 DB 준비 절차. 격리 환경의 SQL 초안 실행 결과는 별도로 기록한다. |
| [T13](../work-orders/initial-30/T13.md) | `main`의 `156f0a2`에 병합된 FastAPI 골격과 기존 스모크 테스트를 기준으로 작업한다. |

착수 시 [API 계약](../API_CONTRACT.md), [전체 범위 추적표](../FULL_SCOPE_TRACEABILITY.md), [DB 모델](../../database/FULL_DATABASE_MODEL.md)을 확인하고 미확정 사항을 기록한다.

## 구현 요구사항

1. **환경 설정** — `backend/app/core/config.py`의 환경변수 기반 설정을 확장한다. 필수 접속값과 연결 풀 설정의 형식·타입·범위를 검증하고, 변수 이름과 예시를 `.env.example`에 기록한다. 비밀번호와 자격정보가 포함된 접속 문자열은 응답, 로그, 예외 메시지, 테스트 증빙에서 마스킹한다.
2. **연결 풀** — `backend/app/db.py` 또는 승인된 경로에 풀과 세션 팩토리를 둔다. 요청마다 풀을 새로 만들지 않고 앱 수명 동안 재사용하며, 앱 종료 시 풀을 정리한다. 접속 실패와 연결 끊김은 호출자가 처리할 수 있는 오류로 전달한다.
3. **요청별 세션** — FastAPI 의존성 `get_db`가 요청별 세션을 제공하도록 한다. `yield`와 `finally`로 정상·예외 경로에서 세션 반납을 보장한다. 실패한 트랜잭션의 롤백과 쓰기 커밋 책임을 명시한다.
4. **권한 분리** — 읽기·쓰기 경로와 각 경로에 필요한 권한을 문서화한다. 앱 실행 계정과 Migration 계정의 책임을 분리한다. 로컬 또는 일회용 DB에서 최소권한 계정으로 검증한다. 공유 Staging 변경에는 승인이 필요하다.

## 인수 기준

| 검증 항목 | 통과 조건 |
| --- | --- |
| 정상 접속 | 유효한 앱 계정으로 `SELECT 1`에 성공하고 세션이 반환된다. |
| 접속 오류 | 잘못된 자격정보와 연결 끊김을 각각 재현해 오류 처리와 비밀값 마스킹을 확인한다. |
| 세션 정리 | 의존성 mock을 사용한 pytest에서 정상 및 예외 경로의 정리를 검증한다. 실패한 트랜잭션이 있는 경우 롤백을 확인한다. |
| 권한 | 준비된 최소권한 계정으로 허용 동작과 권한 거부 사례를 확인한다. 쓰기 계정 준비가 필요한 경우 해당 검증은 `HOLD`로 기록한다. |
| 회귀 | 기존 T13 스모크 테스트를 통과한다. |

PR에 재현 명령, 실행 SHA, 정상·실패 증빙, 영향 범위, 미해결 항목을 기록한다. 리뷰와 CI 결과를 확인하고, CI가 검증 범위를 다루지 못하면 `PARTIAL`로 보고한다. 상태 보고 형식은 [T14 작업지시서](../work-orders/initial-30/T14.md)를 따른다.
