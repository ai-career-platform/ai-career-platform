# T23 — 직무·기술 탐색

상태: **PARTIAL / 검토 요청**. 경로 `/job-roles`, Redmine #1496.

## 화면이 하는 일 (모두 실제 API)

| 기능 | API | 비고 |
|---|---|---|
| 직무 이름 검색 | `GET /v1/job-roles?q=` | 검색어는 URL `?q=`에 남아 새로고침·뒤로가기에서 유지 |
| 목록·페이지 이동 | `GET /v1/job-roles?limit=20&cursor=` | 서버가 총 개수를 주지 않아 "N페이지 · M개 표시"로 범위를 밝힘 |
| 직무 상세·요구 기술 | `GET /v1/job-roles/{id}` | 요구 수준 1~5와 단계 이름(입문~전문가)은 openapi `Level` 표기 |
| **내 보유 기술과 비교** | `GET /v1/me/skills` (T33, 로그인 필요) | 비로그인이면 로그인 안내만 표시하고 호출하지 않음 |

비교는 `충족 / 부족(N단계) / 숙련도 미입력 / 보유 기술에 없음` 네 가지를 숫자 대 숫자로 구분할 뿐 점수·순위를 만들지 않는다. 숙련도 미입력(NULL)은 0으로 바꾸지 않는다(0 처리는 T04 제안이며 PM 승인 전). AI Skill Gap(T26)·추천(T27)은 연결되어 있지 않고 화면에도 그렇게 적는다.

디자인은 T20 공통 컴포넌트(`TextField`, `Button`, `StatePanel`)와 원래 Mock 시안의 히어로·카드·상세 레이아웃을 쓴다. 로딩·빈 결과·오류·재시도, 늦게 도착한 이전 요청 응답 무시(검색·상세·보유 기술 각각)를 처리한다.

## 현재 API가 지원하지 않아 화면에 넣지 않은 것

원래 Mock에 있었으나 T17 계약(`/job-roles`: `q`, `limit`, `cursor`만 지원, 목록 항목은 `job_role_id/code/name`뿐)에 해당 필드가 없다.

- **분야(카테고리) 필터·정렬** — 응답에 분야 필드와 정렬 파라미터가 없다.
- **기술명으로 직무 찾기** — `/skills?q`는 기술 자동완성이며 직무를 기술로 거르는 파라미터가 없다.
- **카드의 설명·기술 칩** — 목록 응답에 설명과 기술이 없고 상세에만 있다.

프런트에서 현재 페이지 20건만 걸러 정렬하면 다른 페이지 결과가 빠져 사용자를 속이게 되므로 만들지 않았다. 복구하려면 T17 담당(Backend)에 `category`·`sort`·`skill_id` 지원과 목록 응답 확장이 필요하다 — 후속 요청 사항이다.

## 실행 및 검증

`frontend`에서 `npm ci`, `npx tsc -b`, `npm test`, `npm run build`. `npm run dev`는 같은 Origin `/api`를 쓰며 `DEV_API_PROXY_TARGET`(예: 허용된 Staging)으로 대상 서버를 고른다. 비밀값을 VITE 변수에 넣지 않는다.

단위 테스트(가상 응답)는 검색·커서·URL 검색어·빈 결과·오류 재시도·늦은 응답 무시·비로그인/로그인 비교·`/me/skills` 실패를 검사한다. 실제 Staging 읽기 확인은 브라우저에서 목록 30건(2페이지)·검색·빈 결과·상세 요구 기술을 확인했다. **로그인 상태의 비교는 테스트 계정이 없어 실 API로 확인하지 못했다**(단위 테스트만).

메뉴와 라우트는 T24 PR과 다른 위치에 넣어 두 PR이 어떤 순서로 병합되어도 충돌하지 않게 했다. 공유 DB·배포 변경은 없다.
